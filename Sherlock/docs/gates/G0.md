## 2. What was built

`Sherlock/sherlock/`: the package and the 11 sub-packages of the module map
(`core data extract grammar stats learn select cond gate eval cli`); all but `core`
and `data` hold only a docstring.

| Module | What it does |
|---|---|
| `data/roots.py` | `resolve_roots()`: env var first, then `config/roots.yaml`; no defaults; a missing root names its variable, its yaml key and `setup.sh`; relative paths and unknown yaml keys are errors; dataset root must exist; `zips` optional. `Roots.sources` records where each root came from |
| `data/manifest.py` | `Manifest` (CSV → `ManifestRow`, sha256 → path; every `dataset_path` checked relative, inside the root and named `<sha256>.bin`; bad or short rows raise with the line number; `resolve_many` drops by reason). `ManifestDB` (`mode=ro&immutable=1`, explicit column lists, chunked `IN` joins, `dropped["no_db_row"]`, `coverage()` for CSV-only and DB-only hashes; six barred columns, below). `Split` (immutable, hashable), `require_training_families`, `LeakageError` |
| `core/ir.py` | redesigned 23 Nov (§2a): `Kind` (five provisional kinds, plain strings), `Occurrence(sha256, section, offset)`, frozen `Candidate` with `value`/`qualifier` (render) and derived `match_key()` (match), `from_bytes()`, `with_occurrences()`, JSONL write/read with `dropped[bad_json/bad_record]` by line |
| `core/records.py` | `RunRecord.start()/finish()/write()` → `ISB_WORK/runs/<experiment>/<arm>/<run_id>/run.json`: git commit and dirty flag of the git root (found from `__file__`), config as strict JSON with no absolute paths (checked at `start()`), each root's source and folder name, UTC start/end, status, stats, drop counts. Outside a repo, git degrades to `error`. `finish()` once only; one folder per run, created exclusively; writes are atomic |

Design choices worth checking:

- **`Occurrence.offset` is a file offset** from the start of the file (not an RVA,
  not section-relative), so YARA `@s` hits, byte-CNN spans and strings compare
  directly (W4). `section` is the header's name, or `None` outside every section or
  when unknown. `offset` is `None` when a value has no single location (imports,
  imphash).
- **Candidate IR:** see §2a (strings exact, imphash strict lower-case, DLL name the
  only folded part of a match key).
- **Barred DB columns:** `file_paths.path`, `files.first_seen_local`,
  `pe_meta.timestamp` (compile time, forgeable), `file_paths.mtime`,
  `archive_extractions.extracted_at` and `errors.subject` (holds dead paths). A read
  raises `ValueError` saying why.
- **The DB opens `mode=ro&immutable=1`.** `mode=ro` alone still updates the `-shm`
  file beside a WAL database. An immutable read ignores the `-wal` file, so
  `ManifestDB` refuses to open while `-wal` is non-empty (a writer that died
  mid-job would otherwise be read around silently). Today's `-wal` is 0 bytes. The
  cost: no locking, so nothing should read the DB while an enrichment job writes it.
- **Run ids** are the start second plus a random suffix; `run.json` is created
  exclusively (`os.link`), so two runs started in the same second can't overwrite
  each other.
- **The leakage guard fails closed:** no split loaded → `LeakageError` for every
  family; no `allow_all` switch (V1 had one). `Split.load()` raises
  `NotImplementedError` until G1 fixes the file format.
- **.NET kinds** arrive with `extract/dotnet.py` (P3, D9).

## 2a. Candidate IR, redesigned from first principles (after brownie's 23 Nov decision)

brownie decided (23 Nov) that Sherlock is not influenced by V1: code is redone from
scratch and only V1's *knowledge* is kept (its style, and its lessons as guards
against known bugs). The first `core/ir.py` was not: its type list, aliases, hex
tokeniser and case-folding set came from V1's `candidate.py`. `data/roots.py`,
`data/manifest.py` and `core/records.py` were written new (the leakage guard's
"raise, no off-switch" is lesson L12, i.e. knowledge), so only `ir.py` is redone.
V1's `candidate.py` was not consulted for the redesign.

**What a candidate is.** An observation about one binary that a YARA rule can test.
YARA tests a file in two ways, so there are two families of kinds:

| Kind | Observation | YARA term it becomes | Render form | Match form |
|---|---|---|---|---|
| `TEXT` | ASCII characters found in the file, `encoding` `ascii` (one byte each) or `wide` (each followed by a zero byte: what YARA's `wide` matches, which is not UTF-16, so non-ASCII text is kept as `BYTES`) | a text string with that encoding modifier | the text, exactly | the text, exactly: YARA text strings are case-sensitive unless `nocase`, and choosing `nocase` is a selection decision, not an observation |
| `BYTES` | a run of concrete bytes | a hex string | lower-case hex, two digits per byte | same |
| `PE_IMPORT` | a function imported by name from a DLL (`qualifier` = DLL, `value` = function) | `pe.imports("dll", "function")` | both names exactly as in the import table | DLL name with A–Z lower-cased (ASCII only), function name exact (YARA compares DLL names case-insensitively: **to pin with a grammar test against the YARA docs in P3**) |
| `PE_SECTION_NAME` | a section name from the header | `pe.sections[i].name == "…"` | exact | exact: `==` is case-sensitive |
| `PE_IMPHASH` | the import hash | `pe.imphash() == "…"` | 32 lower-case hex digits | same |

- **Small and provisional.** More kinds (exports, version info, rich header, .NET
  heaps and references, packing facts) arrive with their extractors in P3; each
  new kind states its render and match forms against YARA's semantics, as above.
- **Observations are concrete.** No wildcards, jumps or alternations in the IR:
  those are rule-writing decisions (grammar, P3), not facts about a sample. So
  `BYTES` holds plain hex and needs no tokeniser.
- **Strict, not forgiving.** An unknown kind, a malformed imphash, non-hex bytes or
  a non-ASCII `ascii` string raises `ValueError` when constructed (Sherlock's own
  extractors are the only producers, so there are no spellings to alias and no
  whitespace to repair). On JSONL read, a bad line is dropped by reason
  (`bad_json`, `bad_record`) with its line number, never crashing the read.
- **Render vs match (lesson L1).** `value`/`qualifier` are the render form;
  `match_key()` derives the match form and is never rendered. For `PE_IMPORT` the
  two differ, so L1 has a real case.
- **Identity** is `(kind, encoding, match form)`: the same observation in two samples
  is one candidate, its occurrences listing both. Tests compare `to_dict()`.
- **Open YARA checks for P3's grammar tests:** whether `pe.imports` folds DLL names (and only ASCII), whether it compares function names exactly, and whether `pe.sections[i].name` strips padding NULs or resolves `/N` long names. The IR accepts names as given until then.
- **Occurrences** are unchanged: `(sha256, section, offset)`, offset a file offset.
- **`meta`**: JSON scalars only (str, int, float, bool, None), so every record
  round-trips; `source` names the extractor that produced it.

## 6. Decisions (brownie, 23 Nov) and what was done

1. **`pe_meta.timestamp` stays barred.** brownie added: signatures can be forged
   too, so we need a way to tell a forged signature from a real one. Measured on
   the working DB (read-only, `immutable=1`):

   | `pe_meta` rows | not signed | signed, LIEF `OK` | signed, not `OK` |
   |---|---:|---:|---:|
   | malware | 71,228 | 2,255 | 4,556 |
   | goodware | 5,846 | 14,252 | 666 |

   The commonest non-`OK` flags are `BAD_SIGNATURE|CERT_EXPIRED` (2,424),
   `BAD_DIGEST|BAD_SIGNATURE` (2,216) and `CERT_NOT_FOUND|BAD_SIGNATURE` (252).
   LIEF's `OK` says the signature is intact against the certificates the file
   carries; as I understand it, it doesn't check the chain against a trusted root
   store, revocation, or whether the certificate was stolen. So the signer columns
   stay readable, but a signer is a *claim*. Proposal, not built: (a) a vendor or
   "signed" fact counts only with `sig_verified = OK`, a chain to a pinned offline
   root bundle, and a valid timestamp countersignature; (b) a known-abused
   certificate list for stolen certificates; (c) the 2,255 `OK`-signed malware
   files measured as the stress set. It bears on W5–W7 (goodware split by vendor),
   on packer and signer features, and on any rule that would use signer fields.
   Needs a decision on where it lives (a W-item or a new risk) before G1.
2. **One folder per run: done.** `runs/<experiment>/<arm>/<run_id>/run.json`. A run id
   is the start second plus a random suffix; a run folder is created exclusively,
   and only the record that created a `run.json` may rewrite it. README,
   SHERLOCKED.md (layout and module map, plan-change row) and CLAUDE.md updated.
3. **Sidecars: deleted.** `manifest.sqlite-wal` (0 bytes) and `-shm` removed after

5. **V1 parity fixtures:** superseded by 7 (§4).
